# بازطراحی «پنجره‌ها» — لایه‌ی پنجره‌های ویرایشگر پروژه

**قدم سومِ بازطراحی UX** — مبنا: گزارشِ میدانیِ کاربر («پنجره‌ها مشکل دارند، یکی می‌رود زیرِ دیگری»)
**دامنه:** پشته‌ی مودال‌ها + پنجره‌های داخلیِ ویرایشگر پروژه (کشوی مالی، نوار تنظیمات بخش، منوهای سرریز)
**پیاده‌سازی:** `webui/css/styles.css` (بخشِ ۱۷ + توکن‌های `:root`)، `webui/js/ui-modal.js` (`syncInert`)، `webui/index.html` (جابه‌جایی `modal-keys`)
**شواهد:** `docs/screenshots/windows-before-*.png` و `docs/screenshots/windows-after-*.png`

---

## ۱) تشخیص: چرا «یکی می‌رفت زیرِ دیگری»؟

پرده‌ی مودال‌ها این‌طور تعریف شده بود:

```css
.modal-backdrop { position: fixed; inset: 0; display: grid; place-items: center; }
.modal          { /* هر پنجره = یک آیتمِ گرید */ }
```

با **یک** پنجره همه‌چیز درست بود. اما ویرایشگر پروژه ذاتاً پشته‌ی دولایه می‌سازد:

| لایه‌ی اول | لایه‌ی دوم | مسیرِ رخداد |
| --- | --- | --- |
| الگوهای یونیت | تأییدِ حذف الگو | ⋯ ردیفِ الگو → «حذف» |
| هر فرمِ پر شده | «تغییرات ذخیره‌نشده دارید» | Esc / ✕ / کلیکِ بیرون روی فرمِ کثیف |
| ریز قیمت‌ها | تأییدِ صدور فاکتور | «صدور فاکتور از این محاسبه» |
| ویرایشگرِ کثیف | «ترکِ ویرایشگر…» | ناوبری هنگامِ داده‌ی ذخیره‌نشده |

گرید برای هر آیتم یک **ردیف** می‌سازد؛ پس دو پنجره‌ی باز به‌جای نشستن روی هم، **زیرِ هم صف می‌کشیدند** (پنجره‌ی دوم پایینِ صفحه، چسبیده به لبه). مجموعِ ارتفاعشان از نمایشگر بیرون می‌زد و چون پرده `fixed` است و `body.modal-open { overflow: hidden }` اسکرول را قفل می‌کند، بخشِ بیرون‌زده **دست‌نیافتنی** می‌ماند. `z-index`های inline (`100`, `102`, …) هم بی‌اثر بودند، چون اصلاً هم‌پوشانی‌ای وجود نداشت که ترتیب بخواهد.

اندازه‌گیریِ واقعی (پیش از تعمیر، viewport برابر ۱۴۴۰×۹۰۰):

```
modal-templates  top:  87  bottom: 489   ← لایه‌ی اول، بالای صفحه
modal-confirm    top: 622  bottom: 813   ← لایه‌ی دوم، ۱۳۳px پایین‌تر، جدا و رها
```

دو باگِ هم‌خانواده که همان بازدید پیدا کرد:

1. **`modal-keys` هرگز دیده نمی‌شد.** این پنجره بیرونِ `#modalBackdrop` نشسته بود و `syncInert()` فقط پنجره‌های داخلِ پرده را `.open` می‌کرد؛ پس «راهنمای کلیدها» (`؟`) برای همیشه `display:none` می‌ماند.
2. **دو فرمِ فعالِ هم‌زمان.** پنجره‌ی زیرین کاملاً کلیک‌پذیر بود؛ کاربر می‌توانست هم‌زمان در دو فرم تایپ کند و بعد نفهمد کدام ثبت شده است.

## ۲) سیستمِ تازه: «یک خانه، یک پشته، یک دسته‌کارت»

### ۲٫۱ همه‌ی پنجره‌ها یک خانه‌ی گرید

```css
.modal-backdrop { display: grid; grid-template: 1fr / 1fr; overflow: auto; }
.modal          { grid-area: 1 / 1; margin: auto; }
```

- `grid-area: 1/1` یعنی همه‌ی لایه‌های باز **روی هم** می‌نشینند؛ حالا `z-index` معنی واقعی پیدا می‌کند.
- `margin: auto` مرکزیتِ «امن» می‌دهد: بر خلافِ `place-items:center`، اگر پنجره‌ای از جعبه بلندتر شود به لبه‌ی بالا می‌چسبد و بریده نمی‌شود.
- `overflow:auto` + `overscroll-behavior:contain` روی پرده و روی خودِ `.modal`: اسکرولِ پنجره هرگز به صفحه‌ی زیرین نمی‌ریزد.
- `max-height: calc(100dvh - 3rem)` تا نوارِ آدرسِ موبایل ارتفاعِ مفید را ندزدد.

### ۲٫۲ دسته‌کارت (deck) — سلسله‌مرتبِ دید

هر پنجره یک متغیرِ `--stack-i` از سمت JS می‌گیرد (۰ = پنجره‌ی فعال):

```css
.modal {
  transform: translateY(calc(var(--stack-i,0) * var(--stack-lift)))
             scale(calc(1 - var(--stack-i,0) * var(--stack-shrink)));
  transition: transform .24s cubic-bezier(.2,.8,.2,1), filter .24s ease, box-shadow .24s ease;
}
.modal.open.beneath { filter: saturate(.55) brightness(.93); box-shadow: var(--shadow-md); pointer-events: none; }
```

- `--stack-lift: -0.8rem` و `--stack-shrink: 0.035` (در موبایل فشرده‌تر: `-0.5rem` / `0.028`).
- لبه‌ی پنجره‌ی زیرین از پشتِ پنجره‌ی بالا پیدا می‌ماند → چشم بدونِ خواندنِ متن می‌فهمد «یک پنجره پشتِ این است».
- بسته‌شدنِ لایه‌ی بالا، پنجره‌ی زیرین را با همان transition به جایگاهِ فعال برمی‌گرداند — حسِ «برگشتن به کارِ نیمه‌تمام».
- `animation-fill-mode` از `both` به `backwards` تغییر کرد؛ وگرنه فریمِ آخرِ انیمیشنِ ورود (`transform:none`) برای همیشه بر عقب‌نشینیِ دسته‌کارت غلبه می‌کرد.

### ۲٫۳ یک پنجره‌ی فعال، نه دو تا

لایه‌های زیرین در `syncInert()` علاوه بر کلاسِ `beneath`، `inert` و `aria-hidden="true"` می‌گیرند:

- موس و Tab و صفحه‌خوان فقط به پنجره‌ی بالا می‌رسند (`pointer-events:none` هم لایه‌ی بیمه‌ی CSS است).
- «اثرِ انگشتِ» Dirty Check از DOM می‌خواند، نه از رویدادها؛ پس `inert` هیچ تداخلی با تشخیصِ کثیفی ندارد.

### ۲٫۴ مقیاسِ لایه‌ها — یک منبعِ حقیقت

عددهای پراکنده‌ی `z-index` به توکن تبدیل شدند تا ترتیبِ دید همیشه قابلِ پیش‌بینی باشد:

```
--z-table-head: 5    سرستونِ چسبان
--z-totalbar:  20    نوارِ جمعِ چسبان
--z-addbar:    21    نوارِ افزودنِ چسبان
--z-editor-bar:24    نوارِ فرمانِ ویرایشگر
--z-topbar:    30    نوارِ عنوان
--z-scrim:     35    پرده‌ی منوی موبایل
--z-sidebar:   40    نوارِ کناری
--z-popover:   60    منوی ⋯ و نتایجِ جست‌وجو
--z-modal:    100    پرده‌ی پنجره‌ها
--z-toast:    200    توست (باید روی پنجره‌ها هم دیده شود)
--z-splash:   500    اسپلش
```

قاعده: **هیچ قاعده‌ی `position`دار جدیدی بدونِ توکن نوشته نشود.**

## ۳) پنجره‌های داخلیِ ویرایشگر پروژه

| پنجره | پیش از این | اکنون |
| --- | --- | --- |
| کشوی «تنظیمات مالی» (`tb-drawer`) | بدونِ حرکت ظاهر می‌شد؛ روی نمایشگرِ کوتاه می‌توانست کلِ ویرایشگر را بپوشاند | ورودِ ۱۸۰ms با `sheetIn` + سقفِ `min(56vh,26rem)` و اسکرولِ داخلی |
| نوارِ «تنظیمات بخش» (`section-bar`) | پرشِ ناگهانی هنگامِ باز شدن | همان ورودِ نرم — جهتِ باز شدن را به چشم نشان می‌دهد |
| منوی سرریز `⋯` و منوی split (`ovf-menu`) | بدونِ حرکت؛ فهرستِ بلند می‌توانست از نمایشگر بیرون بزند | ورودِ ۱۴۰ms + سقفِ `min(70vh,24rem)` با اسکرولِ داخلی |

این‌ها «پنجره» به معنای مودال نیستند، ولی همان قراردادِ لایه‌ای را رعایت می‌کنند: هر سطح یک توکنِ z، هر ورود یک حرکتِ جهت‌دارِ کوتاه، و هرگز سرریزِ بی‌اسکرول نیست.

## ۴) تغییرات به‌تفکیکِ فایل

- **`webui/css/styles.css`**
  - بخشِ ۱۷ بازنویسی شد: خانه‌ی مشترکِ گرید، مرکزیتِ امن، دسته‌کارت، `dvh`، `overscroll`.
  - توکن‌های `--z-*` و `--stack-*` در `:root`؛ همه‌ی قواعدهای پیشین به توکن وصل شدند.
  - قاعده‌ی کهنه‌ی `.modal-backdrop .modal.open.beneath { filter: … }` (بخشِ ۲۴) حذف شد تا با تعریفِ جدیدِ بخشِ ۱۷ نزاع نکند.
  - چاپِ برش‌نامه: `grid-area:auto; margin:0; transform:none; filter:none` و `display:block` روی پرده تا چاپِ تک‌پنجره‌ای دست‌نخورده بماند.
  - موبایل (≤۶۴۰px): ضریب‌های فشرده‌ترِ دسته‌کارت.
- **`webui/js/ui-modal.js`** — `syncInert()`: تنظیمِ `--stack-i` و `z-index` نسبی، `inert`/`aria-hidden` روی لایه‌های زیرین، و پاک‌سازیِ styleهای inline هنگامِ بسته‌شدن.
- **`webui/index.html`** — `#modal-keys` به داخلِ `#modalBackdrop` منتقل شد (پنجره‌ای که هرگز باز نمی‌شد).
- **`webui/kabir-ui-standalone.html`** — با `build_standalone.py` بازساخته شد.

## ۵) پذیرش (Acceptance)

1. هر ترکیبِ دولایه در ویرایشگر (الگو+تأیید، فرمِ کثیف+هشدار، ریزقیمت+فاکتور) → پنجره‌ی دوم **روی** اولی، مرکزِ صفحه؛ لبه‌ی اولی پیدا و کم‌رنگ. (`windows-after-stack.png`, `windows-after-guard.png`)
2. پشته‌ی سه‌لایه → ترتیبِ دید و `z-index` درست؛ فقط لایه‌ی بالا تعامل می‌کند (`document.getElementById('modal-x').inert`).
3. موبایل ۳۹۰×۸۴۴ → هشدارِ ذخیره‌نشده روی خودِ فرم، نه لبه‌ی پایینِ صفحه. (`windows-after-stack-mobile.png`)
4. `؟` → راهنمای کلیدها باز می‌شود.
5. چاپِ برش‌نامه (`Ctrl+P` در مودال کارگاه) بدونِ تغییر نسبت به قبل.
6. تست‌های موجود سبز: `node tests/ui_modal_guard_check.js` (۱۰۵ بررسی)، `ux_flow_test` (۲۶)، `ux_doors_test` (۳۰)، `workshop_check` (۱۰۵)، `ui_dom_check`، `ui_features_check`.
