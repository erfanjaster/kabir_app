# وایرفریم متنی — لایه‌ی مشترک «مودال و فرم» کبیر

**قدم دومِ بازطراحی UX** — مبنا: `docs/UX_AUDIT_v1.md`
**دامنه:** هر ۱۰ مودال + هر ۶ فرم + مسیرهای خروجِ ویرایشگر پروژه
**پیاده‌سازی:** `webui/js/ui-modal.js` (تازه)، `webui/js/ui.js`، `webui/index.html`، `webui/css/styles.css`

---

## ۱) اصلِ حاکم: «یک لایه، یک قرارداد»

به‌جای ۲۰ نقطه‌ی پراکنده‌ی خروجِ بی‌قید، همه‌ی مودال‌ها از **یک** ماشینِ وضعیت عبور می‌کنند:

```
                    ┌──────────────────────────────────────────┐
   کاربر مودال باز   │            MODALS.stack (پشته)            │
   می‌کند ───────────▶  [ material ]                              │
                    │  [ templates, confirm ]  ← لایه‌ی دوم       │
                    └──────────────────────────────────────────┘
                                     │
                 هر کنشِ خروج (✕ / انصراف / Esc / کلیک بیرون)
                                     ▼
                         ┌───────────────────────┐
                         │  isModalDirty(top) ؟  │  ← مقایسه‌ی «اثرِ انگشتِ»
                         └───────────────────────┘    فرم با لحظه‌ی بازشدن
                            │تمیز            │کثیف
                            ▼                ▼
                     بستنِ بی‌صدا     لایه‌ی «تغییرات ذخیره‌نشده»
                     (۰ کلیک اضافه)          │
                                    ┌────────┼─────────┐
                                    ▼        ▼         ▼
                              ادامه‌ی ویرایش  ذخیره و بستن  دور ریختن
```

**چرا «اثرِ انگشت» (fingerprint) و نه یک پرچمِ `dirty` ساده؟**
چون کاربر ممکن است فیلدی را عوض کند و **به مقدارِ اول برگرداند**. در آن حالت
پرسیدنِ «ذخیره‌نشده دارید» یک مزاحمتِ بیهوده است. مقایسه‌ی `value`/`checked`/
`selected` + ترتیبِ گزینه‌های هر `select` با لحظه‌ی بازشدن، دقیقاً همان چیزی است
که قانون می‌خواهد: *«اگر کاربر فرمی را پر کرده باشد»*.

## ۲) وایرفریمِ فرمِ موجود در مودال (بدونِ تغییرِ چیدمانِ فعلی — فقط قرارداد)

چیدمانِ فعلیِ کبیر در این بخش **درست** بود و حفظ شد (قانونِ ثبات رویه):

```
┌──────────────────────────────────────────────────────────────────────┐
│  افزودن قلم                                          [ذخیره‌نشده] ✕   │  ← modal-head چسبان
│                                                     ─────────────     │     نشانِ زنده‌ی «پر شده»
├──────────────────────────────────────────────────────────────────────┤
│  نام قلم  [ ام‌دی‌اف سفید صدفی ۱۶ میل                          ]      │  ← data-autofocus
│  دسته‌بندی [ ورق بدنه        ▾]   واحد [ ورق ▾]                        │     فوکوسِ اولیه = اولین
│  قیمت     [ ۱٬۲۵۰٬۰۰۰ ] ⚠ قیمت باید عددی بزرگ‌تر از صفر باشد.          │     فیلدِ «معنادار»
│           └── خطا کنارِ خودِ فیلد + aria-invalid (نه فقط توست)          │
│  …                                                                     │
├──────────────────────────────────────────────────────────────────────┤
│  ⌨ Enter  ذخیره‌ی قلم      [ ذخیره‌ی قلم ]        [ انصراف ]            │  ← modal-foot چسبان
│  └ راهنمای کلید            └ کنشِ اصلی: راست،      └ چپ                │
│                              بزرگ، primary                             │
└──────────────────────────────────────────────────────────────────────┘
```

**ثبات در هر ۱۰ مودال:** کنشِ اصلی همیشه **راست** (در RTL = ابتدای مسیرِ چشم)،
«انصراف» همیشه **چپ**، و راهنمای `Enter` همیشه در ابتدای پاورقی.
حافظه‌ی عضلانیِ اپراتور بعد از چند روز به «پایین‑راست = ثبت» قفل می‌شود.

## ۳) لایه‌ی «تغییرات ذخیره‌نشده دارید» — قلبِ قانونِ اول

```
        ┌────────────────────────────────────────────────────────┐
        │  ⚠  تغییرات ذخیره‌نشده دارید                        │  ← سربرگِ کهربایی
        ├────────────────────────────────────────────────────────┤   (هشدار، نه خطر)
        │  «فرمِ متریال» بسته نشده است — ۲ فیلد تغییر کرده.      │
        │  اگر ببندید، این اطلاعات از بین می‌رود.                │  ← شمارشِ واقعیِ فیلدها
        ├────────────────────────────────────────────────────────┤
        │  [ ✎ ادامه‌ی ویرایش ]  [ 💾 ذخیره و بستن ]    دور ریختن │
        │    ↑ امن‌ترین کنش      ↑ فقط اگر فرم        ↑ کوچک،     │
        │      = فوکوسِ اولیه       ثبت‌شدنی باشد       کم‌رنگ،   │
        │      و بزرگ‌ترین هدف                          چپِ دور   │
        └────────────────────────────────────────────────────────┘
```

### سه تصمیمِ ارگونومیک که اینجا گرفته شد

| تصمیم | دلیل (بر پایه‌ی قوانینِ شما) |
| --- | --- |
| **«ادامه‌ی ویرایش» بزرگ‌ترین هدف و فوکوسِ اولیه است** | فیتز + «کمترین هزینه برای امن‌ترین کنش». اپراتوری که ۸ ساعت کار می‌کند و دستش به Esc می‌خورد، با یک Enter برمی‌گردد سرِ کارش |
| **«دور ریختن» کوچک، کم‌رنگ، با خط‌چین و `margin-inline-start: 1.4rem`** | قانونِ ۲‑بند‑۲: *«دکمه‌های خطرناک باید از دکمه‌های اصلی فاصله داشته باشند»*. عمداً از خانواده‌ی `btn` بیرون برده شد تا هم‌اندازه‌ی دو کنشِ دیگر نباشد |
| **«ذخیره و بستن» فقط وقتی فرم `save` داشته باشد** | در مودالِ برش‌نامه یا ریزِ قیمت‌ها که چیزی برای ثبت نیست، گزینه‌ی توخالی نشان نمی‌دهیم (بارِ شناختیِ بیهوده) |
| **Esc روی این لایه = «ادامه‌ی ویرایش»** | امن‌ترین تفسیر. کاربرِ خسته که Esc می‌زند باید به کارش برگردد، نه اینکه داده‌اش برود |

## ۴) پشته‌ی مودال‌ها — رفعِ باگِ فروپاشیِ لایه (C‑6)

**قبل:** همه‌ی مودال‌ها در یک `backdrop` تخت؛ `closeModal()` همه را با هم می‌بست.

```
   قبل  ─────────────────────────────       بعد  ─────────────────────────────
   [ فهرست الگوها ]                          [ فهرست الگوها ]  ← inert, aria-hidden
        └─ «حذف الگو» → [ تأیید ]                 └─ «حذف الگو» → [ تأیید ] ← لایه‌ی بالا
             Esc ✕ انصراف  →  💥 هر دو بسته            Esc ✕ انصراف  →  فقط «تأیید» بسته
             → کاربر از اول مسیر می‌رفت                 → کاربر سرِ فهرستِ الگوها می‌ماند
```

قانونِ پشته:
- `openModal(id)` → **push** (اگر همان مودال از قبل باز بود، به بالای پشته منتقل می‌شود)
- `closeModal(id?)` → **pop** یک لایه (پیش‌فرض: بالایی) + بازگرداندنِ فوکوس به لایه‌ی زیرین
- `closeAllModals()` → فقط برای خروجِ کامل
- لایه‌های بسته `inert` + `aria-hidden` می‌شوند → **Tab هرگز به DOMِ نامرئی فرار نمی‌کند**
- تورِ پس‌زمینه با عمقِ پشته تاریک‌تر می‌شود (`stacked-2`, `stacked-3`) تا کاربر بداند کجای کار است

## ۵) قراردادِ سراسریِ صفحه‌کلید

| کلید | در مودالِ باز | در صفحه (بدونِ مودال) |
| --- | --- | --- |
| `Enter` | ثبتِ فرم (در `textarea` و روی `button` نه) | — |
| `Ctrl+Enter` | ثبتِ فرم (همیشه، حتی در textarea) | — |
| `Ctrl+S` | ثبتِ مودالِ بالایی | ذخیره‌ی زمینه: ویرایشگر پروژه / تنظیمات |
| `Esc` | بستنِ **یک** لایه با شرطِ کثیفی | بستنِ دراپ‌داونِ جست‌وجو و منوی موبایل |
| `Tab` | چرخشِ محصور در مودالِ بالایی | طبیعی |
| `/` | (غیرفعال) | فوکوس روی جست‌وجوی سراسری |
| `Alt+1..6` | (غیرفعال — تا داده‌ی فرم نپرد) | ناوبریِ صفحه‌ها **با گاردِ خروج** |
| `Ctrl+Z` / `Ctrl+Shift+Z` | (غیرفعال) | واگرد/بازانجامِ ویرایشگر |

> **نکته‌ی مهم:** `Alt+1..6` و `/` وقتی مودالی باز است **غیرفعال** شدند. قبلاً
> `Alt+2` وسطِ پرکردنِ فرمِ متریال، کاربر را به صفحه‌ی دیگر می‌برد و داده می‌پرید.

## ۶) گاردهای خروج از ویرایشگر پروژه (C‑5)

پنج مسیرِ خروج وجود داشت که فقط یکی محافظت‌شده بود. حالا همه از یک گارد می‌گذرند:

```
  هر درخواستِ خروج
        │
        ▼
  ┌───────────────────────────────┐
  │ ویرایشگر باز و state.dirty ؟   │──نه──▶  برو (بدونِ مزاحمت)
  └───────────────────────────────┘
        │بله
        ▼
  ┌───────────────────────────────┐
  │ مقصد = خودِ صفحه‌ی پروژه‌ها ؟    │──بله─▶  برو (ویرایشگر در همان صفحه است؛
  └───────────────────────────────┘          داده‌ای گم نمی‌شود ← مزاحمِ کاربر
        │نه                                   ۳۰ بار در روز نمی‌شویم)
        ▼
  ┌───────────────────────────────┐
  │ ۱) تلاش برای ذخیره‌ی بی‌صدا     │──موفق─▶  برو + توستِ «ذخیره شد»
  └───────────────────────────────┘          (کمترین اصطکاک: ۰ کلیک)
        │ناموفق
        ▼
  ┌───────────────────────────────┐
  │ ۲) پرسشِ صریح                  │──«دور ریختن و رفتن»─▶  بستن + رفتن
  │    «ترکِ ویرایشگر»              │──«انصراف»────────────▶  ماندن + اسکرول
  └───────────────────────────────┘                            به ویرایشگر
```

**مسیرهای تحت پوشش:** کلیکِ منوی کناری، `Alt+1..6`، نتیجه‌ی جست‌وجوی سراسری،
`hashchange`، «بازکردنِ» پروژه‌ی دیگر در جدول، «کپی پروژه»، «بستنِ ویرایشگر»،
و `beforeunload` (حالا در حالتِ نمایشی هم فعال است).

### یک تصمیمِ سیاستی که باید تأییدش کنید
گارد **اول سعی می‌کند بی‌صدا ذخیره کند** و فقط اگر ذخیره ناموفق بود می‌پرسد.
استدلال: قانونِ «حذف کلیک‌های اضافی» + «هرگز داده را دور نریز» با هم.
اگر سیاستِ سخت‌گیرانه می‌خواهید (همیشه بپرس)، تغییرش **یک خط** است:
در `editorExitGuard` همان اول `return confirmDiscard(...)`.

## ۷) ثبتِ فرم: یک راه برای همه

```
   کلیکِ کنشِ اصلی ─┐
   Enter ───────────┤
   Ctrl+Enter ──────┼──▶  submitModal(id)  ──▶  busy(btn)  ──▶  cfg.save()
   Ctrl+S ──────────┤                                              │
   «ذخیره و بستن» ──┘                            ┌─────────────────┴──────────────┐
                                            false│ (اعتبارسنجی رد شد)         true │
                                                 ▼                                ▼
                                     مودال باز می‌ماند              markModalDirty(false)
                                     خطا کنارِ فیلد + فوکوس          closeModal(id)
                                     روی اولین فیلدِ خطادار          + توستِ موفقیت
```

**چرا این مهم است؟** قبلاً هر دکمه هندلرِ خودش را داشت و `Enter` در ۵ فرم از ۶
کار نمی‌کرد. حالا «ثبت» یک مفهومِ واحد است؛ افزودنِ فرمِ جدید یعنی **یک ردیف**
در `MODAL_FORMS` — بقیه‌ی رفتار (Esc، کلیک بیرون، Enter، تله‌ی فوکوس، هشدارِ
ذخیره) خودکار به ارث می‌رسد.

### الگوی افزودنِ فرمِ جدید (۳ خط)
```js
const MODAL_FORMS = {
  …,
  myForm: { label: "فرمِ من", save: "saveMyForm", saveBtn: "btnSaveMyForm",
            hint: "Enter = ثبت" },
};
// و داخل wire():  registerModalForms({ …, saveMyForm });
// تابعِ ثبت: async function saveMyForm(){ … return true|false; }
```

## ۸) اعتبارسنجی: پیام آن‌جا که چشم هست

**قبل:** `toast("نام قلم را وارد کنید", "error")` → توست در پایین‑چپِ صفحه،
۱۰۰۰ پیکسل دور از فیلدی که ایراد دارد. کاربر باید حدس بزند کدام فیلد است.

**بعد:**
```
   قیمت  [ ۰ ]
         ⚠ قیمت باید عددی بزرگ‌تر از صفر باشد.     ← .field-err + role="alert"
         └ فیلد قرمز + aria-invalid + فوکوس و اسکرول به اولین فیلدِ خطادار
```
توست **هم** سرِ جایش است (برای موفقیت‌ها)، اما خطا حالا کنارِ علتش می‌نشیند.

## ۹) نکاتِ پیاده‌سازی که در ممیزی پیدا شد و باید بدانید

1. **`build_standalone.py` و ۴ هارنسِ تست، فهرستِ فایل‌های JS را هاردکد کرده بودند.**
   هر سه به‌روز شدند (`JS_FILES = ("data","engine","ui-modal","ui")`). اگر این
   را ندیده بودم، `kabir-ui-standalone.html` (۸۷۳۳ خط، داخلِ مخزن) بی‌سروصدا
   **فاقدِ کلِ این لایه** ساخته می‌شد. این در `webui/README.md` مستند شد.
2. **`mousedown` به‌جای `click` برای کلیکِ بیرون.** اگر کاربر داخل مودال متن
   انتخاب کند و دستش را بیرون رها کند، `click` روی backdrop شلیک می‌شد و فرم
   می‌پرید. با `mousedown` فقط «کلیکِ واقعی روی پرده» خروج حساب می‌شود.
3. **در حالتِ strict، تابعِ سطح‌بالا به `window` نمی‌چسبد** — پس رجیستریِ فرم‌ها
   با «ارجاعِ تابع» پر می‌شود نه با نامِ رشته‌ای. (این دقیقاً همان چیزی است که
   باعث شد تست‌ها اول شکست بخورند و باگ را لو بدهند.)
4. **`confirmCb` معلق:** رد کردنِ مودالِ تأیید با Esc دیگر callback را رها نمی‌کند؛
   `onClose(dismissed)` صریحاً «رد شد» را اطلاع می‌دهد و `confirmDiscard()`
   یک `Promise<boolean>` برمی‌گرداند.

## ۱۰) آنچه عمداً در این قدم تغییر نکرد

- چیدمانِ داخلیِ فرم‌ها (ستون‌ها، ترتیب فیلدها) — دست‌نخورده، چون ممیزی آن‌ها را
  سالم دانست؛ مشکل «مکانیزمِ خروج» بود نه چیدمان.
- جای کنشِ اصلی/انصراف — همان الگوی درستِ قبلی حفظ و **مستند** شد.
- جدول‌های ویرایشگر، نوارِ جمع، صفحه‌ی فاکتور → **F‑1 تا F‑6**، یعنی P2 که
  قدمِ بعدی است.
